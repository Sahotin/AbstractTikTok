# 简历与面试指南

## 1. 项目名称

**AbstractTikTok — 视频评论智能分析与舆情 Tool Calling Agent**

## 2. 简历项目描述（可直接调整）

- 基于 MediaCrawler 构建采集与 AI 分析解耦的数据链路，设计内容、评论、作者和采集运行统一模型，以 SQLite/Alembic 完成幂等导入、版本迁移和只读查询 API。
- 实现 DeepSeek 结构化评论分析 Pipeline，使用 JSON Object + Pydantic 校验，支持缓存、指数退避、并发/速率限制、失败隔离、任务状态和成本估算，避免逐条无控制调用 LLM。
- 基于 Qwen3 Embedding 实现版本化向量缓存、确定性主题聚类、代表评论与语义检索；真实数据完成 1,907/1,907 向量生成，13 个批请求、17.8 秒，向量维度 2,560。
- 设计情感/情绪/立场/风险 SQL 聚合、时间趋势和可解释风险分；加入低信息评论质量门，排除 814/1,907 条无效语义输入，将最大噪声簇从 418 条降至 20 条。
- 实现包含 8 个只读工具的 DeepSeek Tool Calling Agent，通过作用域校验、最多 8 次工具调用、重复调用阻断和工具结果截断控制无限循环与上下文膨胀。
- 使用 FastAPI 提供 OpenAPI、后台分析任务和 Dashboard；152 项分析层测试通过，并在验证数据库上完成真实 DeepSeek、Embedding、语义检索和 Agent 端到端验收。

不要写“全量 1,907 条已完成 LLM 情感分析”。真实完成的是 3 条 DeepSeek 结构化输出验证和 1,907 条 Embedding；这一区分是面试可信度的一部分。

## 3. 60 秒项目介绍

“项目最初是基于 MediaCrawler 定制的多平台采集工具。我没有继续堆爬虫平台，而是在采集层上面增加了独立 AI 应用层。数据先进入内容、评论、作者统一模型，再通过 DeepSeek 做结构化情感、主题、立场和风险分析；大规模处理使用持久任务、并发和速率限制、缓存与失败隔离。语义侧使用 Qwen Embedding，固定数据快照后做主题聚类、代表评论和相似评论检索。上层有 SQL 舆情聚合、趋势和风险评分，最后由一个真正的 Tool Calling Agent 自主选择 8 个只读工具回答问题。项目重点不是调用一次 API，而是可复现、可观测、可测试并能诚实处理覆盖率不足的完整 AI 工程链路。”

## 4. 高频面试问题

### 为什么不用 `for comment: call_llm(comment)`？

因为它没有并发上限、限流、失败状态、缓存和成本边界。项目先创建固定 Job Item，再由有界 worker 拉取批次；单条失败不会让整批不可恢复，重跑时先查版本化缓存。

### 为什么 DeepSeek 使用 `json_object`？

真实 API 验证发现当前模型拒绝 `json_schema` response format，但支持 JSON Object。因此由配置显式选择模式，把 Pydantic JSON Schema加入提示词，返回后仍由 Pydantic严格校验。没有自动重发到另一模式，以免一次逻辑请求产生双倍付费。

### 为什么暂时不用向量数据库？

当前单快照上限 5,000，NumPy 内存余弦检索简单、可测试且没有额外运维成本。Embedding 已经版本化持久化，未来数据量上升时可将检索边界替换为 pgvector/Qdrant，而不改变 Agent Tool schema。

### 聚类为什么需要质量门？

真实评论中纯数字、表情和“哈哈”等高频低信息文本会形成巨大簇，数学上紧密但业务上无意义。质量门不删除数据，只在语义运行中标记排除原因。真实实验中排除 42.68%，最大簇从 418 降到 20，主题可解释性显著提升。

### 如何避免 Agent 无限调用？

四层边界：请求最大步骤、工具调用总数、相同工具参数签名去重、单工具/总上下文字符上限。达到边界后关闭工具并强制模型基于已有证据总结。

### 风险分可靠吗？

它不是概率。当前使用负面比例 50%、高风险比例 35%、中风险比例 15% 的透明规则形成 0–100 排序信号，同时返回分析覆盖率。低覆盖率时 Agent 必须说明“不足”，不能把未分析当作低风险。

### 项目还有哪些生产化缺口？

多平台 normalizer、全量真实 LLM 标注评估、模型输出人工标注集、外部任务队列、鉴权与配额、向量索引、监控告警和 CI/CD。能明确边界比声称“已生产可用”更可信。

## 5. 演示顺序

1. 在 `/` 展示采集任务与实时日志。
2. 在 `/dashboard` 展示总量、覆盖率、趋势和主题代表评论。
3. 用“如何报名学习”演示语义检索。
4. 向 Agent 提问“用户最关心什么，证据是否充分”。
5. 打开 Agent trace，解释模型实际调用了哪些工具。
6. 展示主题质量报告与 152 项测试结果，说明真实数据边界。

## 6. 值得继续做与不值得堆砌

优先：人工标注小型评测集、多平台标准化、异步队列、API 鉴权、可观测性、语义检索索引化。

暂不优先：为了简历引入 LangChain、多 Agent 协作、知识图谱、微服务拆分或 Kubernetes。当前规模下这些会增加复杂度，但不能证明更强的问题解决能力。
